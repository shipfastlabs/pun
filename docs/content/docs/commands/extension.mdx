title: pun extension

---

List the built-in extensions and whether each is on. An extension adds rules for a framework or test tool.

## Usage

```bash
pun extension list [options]
```

```bash
pun extension list
pun extension list --format json
```

## Options

| Option | Description |
| --- | --- |
| `--format json` | Print JSON. |
| `--config <path>` | Use this `pun.toml`. |

## What happens

- Prints each extension, `on` or `off`, and why.
- If a package is in `composer.lock` but its extension is off, shows the line to add.

```text
laravel           on   Laravel's rules and Larastan's analysis: on in pun.toml
pest              off  Rules for Pest tests: pestphp/pest v4.1.0 is locked; turn it on with pest = "on" in [extensions]
phpunit           off  Rules for PHPUnit tests: not in pun.toml
carbon            off  Carbon's macros and DatePeriodBase in analyse: not in pun.toml
mockery           off  phpstan-mockery's mock types in analyse: not in pun.toml
disallowed-calls  off  The calls and uses your config forbids, in analyse: not in pun.toml
type-coverage     off  Minimum shares of declared types, in analyse: not in pun.toml
```

| Extension | Adds |
| --- | --- |
| `laravel` | Laravel lint and analyse rules, and Larastan's checks. |
| `pest` | Pest lint rules, and pest-plugin-phpstan's types in analyse. In a test or a hook (`test()`, `it()`, `describe()`, `beforeEach()`, `afterEach()`, `beforeAll()`, `afterAll()`), `$this` is the test case that `pest()->extend()` or `uses()` binds to the file's directory in `tests/Pest.php`, else `PHPUnit\Framework\TestCase`, and the closure can call its protected methods. A test case takes any property, and `$this->name` read in a test has the types the file's `beforeEach()` closures assign to it. A binding made in the test file itself isn't read. |
| `phpunit` | PHPUnit lint rules. |
| `carbon` | Carbon's PHPStan extension in analyse. Each class that implements `CarbonInterface` gets the macros that `X::macro('name', ...)` calls register in the analysed, scanned, and bootstrap files. Pun reads these calls without running PHP. A macro that is registered at runtime in any other way, such as with a dynamic name, isn't found. |
| `mockery` | phpstan-mockery's PHPStan extension in analyse. `Mockery::mock()`, `spy()` and `namedMock()` return `MockInterface` intersected with the classes their string arguments name, `allows()` and `expects()` on a mock of one class accept any method and return `Expectation`, and a PHPDoc `MockInterface\|Foo` reads as `MockInterface&Foo`. It adds no rules. |
| `disallowed-calls` | spaze/phpstan-disallowed-calls' rules in analyse, in the `disallowed` group. Each rule reads its lists from its options, such as `calls` on `disallowed/function`, and reports nothing until a list has entries. |
| `type-coverage` | tomasvotruba/type-coverage's four rules in analyse, in the `type-coverage` group: `analyse/type-coverage/return`, `param`, `property` and `constant`. Each reports every declaration without a native type when fewer than its `min` percent (default 99) of the project's declarations have one. `measure = true` reports the coverage instead. They report nothing when `pun analyse` gets paths other than the configured ones. The bundled rector/type-perfect rules aren't ported. |

An extension is on only when [`[extensions]`](/docs/configuration/pun-toml#extensions) says `"on"`. `pun init` and `pun migrate` write that for you.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Printed. |
| 2 | The config could not be read. |
