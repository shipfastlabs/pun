## Config translation

`pun migrate` keeps the old config and reports what it skips. Planned rules do not run.

Run `pun migrate --from phpstan`. It follows the config's includes. That covers includes that an included `.php` file builds with variables, `foreach`, `if`, `glob()`, `is_file()`, `class_exists()`, and `interface_exists()`. `class_exists()` and `interface_exists()` know only PHP's and PHPStan's own classes. An included `.php` file that uses anything else, or asks about any other class (such as one from a PHPStan extension in `vendor/`), is reported and skipped: the rest of the config is migrated, without that file's parameters. When another file uses a parameter that only the skipped file defines, the migration stops with an error that names the skipped file.

| phpstan.neon | pun.toml |
| --- | --- |
| `level: 5` | `[analyse] preset = "phpstan/level_5"`, which runs exactly PHPStan's level 5 |
| `level: 0..10`, `level: max` | `preset = "phpstan/level_<n>"` or `"phpstan/level_max"`, with on/off lines only for what the config changes, such as opt-in checks or strict-rules. `--offer-preset` offers Pun's closest preset instead |
| `paths`, `excludePaths`, `stubFiles` | `[analyse] paths`, `exclude`, `stubs` |
| `scanFiles`, `scanDirectories`, `bootstrapFiles` | `[analyse] scan` and `bootstrap`. Files of a built-in extension, such as Larastan's, come with the extension and aren't copied. Other `vendor/` files, such as `php-stubs/wordpress-stubs`, are copied, in `stubs` too |
| `ignoreErrors` identifiers, patterns, paths, count, `reportUnmatched` | `[[analyse.ignore]]` with Pun `rule`, original `identifier`, `message`, `paths`, `count`, `report-unmatched` |
| `reportUnmatchedIgnoredErrors: false` | `[analyse] report-unmatched = false`, and `report-unmatched = false` on each entry that doesn't set `reportUnmatched` |
| Changed rule parameters | Kebab-case options on each running rule that reads the parameter |
| strict-rules or deprecation-rules includes | The matching Pun checks, when their parameter enables them |
| nesbot/carbon's `extension.neon` | Built in: `carbon = "on"` in `[extensions]` when composer.lock locks `nesbot/carbon` |
| phpstan-mockery's `extension.neon` | Built in: `mockery = "on"` in `[extensions]`. `mockery.convertUnionToIntersectionType: true` needs no line, as Pun always converts; `false` is reported as unsupported |
| spaze/phpstan-disallowed-calls' or tomasvotruba/type-coverage's `extension.neon` | Built in: `disallowed-calls = "on"` or `type-coverage = "on"` in `[extensions]`. When phpstan.neon doesn't load the package but composer.lock locks it, the switch is `"off"`, because PHPStan doesn't run its rules |
| `type_coverage` parameters | `min` on each `analyse/type-coverage/*` rule, from `return_type` or its alias `return`, which wins when set. `measure` goes on all four. The deprecated `declare` and `print_suggestions` are reported and skipped |
| `disallowedFunctionCalls`, `disallowedMethodCalls` and the other `disallowed*` lists | The `calls`, `namespaces`, `constants` and other options of the `disallowed/*` rules, with kebab-case entry keys (`allow-in`). Bundled configs such as `disallowed-dangerous-calls.neon` are copied entry by entry. `allowIn`, `allowExceptIn`, `disallowIn` and `definedIn` paths become relative to the project root, so `filesRootDir` and `allowInRootDir` aren't copied. An `ignoreErrors` entry for an entry's `errorIdentifier` goes to that entry's rule |
| A check that is a lint rule in Pun (`array.duplicateKey`) | The lint rule, on in `[[lint.overrides]]` for `paths` and off for `excludePaths`, unless another config turns it on everywhere. `pun analyse` also reports the check's errors under the lint rule's ID, because the lint rule sees no types and can miss some |
| `@phpstan-ignore method.notFound` | `@pun-ignore analyse/undefined/method` |
| Baselines | Not copied. Run `pun analyse --generate-baseline`, and `pun lint --generate-baseline` for the checks that became lint rules. |
| `bleedingEdge.neon` include | `[analyse] bleeding-edge = true`, and an `"on"` line for each rule it turns on |
| `phpVersion: 80400`, or `{min, max}` | `[php] version = "8.4"`, from `min`. A different `max` is reported and skipped |
| Custom extensions, `rules:` classes, services tagged `phpstan.*` | Reported and skipped, one line each |

The rule mapping lists PHPStan identifiers. An exact identifier wins over a pattern.
