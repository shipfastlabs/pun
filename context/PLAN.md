## 2. Decisions

All from Pushpak unless marked "assistant's call"; dated 2026-10-17 unless given.

### Product

- **Home and licence:** github.com/shipfastlabs/pun, public, MIT (LICENSE, licenses/THIRD_PARTY_NOTICES.md). Not a
  shipfastlabs project. The docs site is https://punphp.com.
- **Positioning:** Pun is to PHP what Bun is to JavaScript: one native binary that formats, lints and analyses PHP and
  installs Composer packages. Each command gives the same answers as the tool it replaces (Pint and PHP-CS-Fixer,
  Rector, PHPStan and Larastan, Composer), so a project can switch one command at a time. Laravel first, PHP 8.3+
  projects only.
- **1.0 ships everything at once.** 0.x releases come first; the site presents 1.0 only when `pun format`,
  `pun analyse`, `pun lint` and `pun migrate` all meet the 1.0 bar below. Publishing needs Pushpak's go.
- **The 1.0 bar:** every lint rule in mapping.toml native; every PHPStan core rule native; Larastan built in with seven
  improvements (typed config, routes, views, translations, env keys, Inertia pages, fresh model data); deprecation-rules
  and strict-rules as plain rules. Speed and memory come first in every command.
- **Shipping** (2026-11-14, plan/foundations.md §4): the Composer package `shipfastlabs/pun` (`composer.json` at the root;
  the shim `composer/bin/pun` downloads the release archive for the platform, checks its SHA-256 and runs it) and the
  standalone installer `curl -fsSL https://punphp.com/install | sh`. Release archives carry GitHub build
  attestations. No crate, npm package or Homebrew tap (`publish = false` in every crate).
- **Package manager** (2026-11-15, plan/packages.md): composer.json and composer.lock hold the dependencies, as
  package.json and bun.lock do for Bun; pun.toml holds only `[workspace]` and Pun's own settings. `pun migrate` leaves
  composer.json and composer.lock alone, so `composer` keeps working beside `pun`.
- **No published benchmarks** (Pushpak, 2026-11-23): the docs, README and homepage say Pun is fast, with no figures and
  no comparisons with other tools. `scripts/bench.py` stays an internal perf check (scripts/lint-vs-rector.py uses its
  setup); its results are not recorded or published.
- **Brand:** "Sticker Pop", the sprinting elephant in sneakers; Fredoka for text, Martian Mono for code (docs/design/).

### Commands (plan/commands.md)

- **One job each.** `pun format`: how the code looks (layout, casing, spelling; never changes behaviour, never deletes
  code). `pun lint [--fix]`: a better way to write it (Rector, PHP-CS-Fixer's risky fixers, Mago's lint rules, version
  upgrades). `pun analyse` / `analyze`: is it wrong (PHPStan, Larastan; never edits). `pun check [--fix]`:
  lint fixes, then format, then analyse, in one pass; the command for CI and agents.
- **Placement:** a rule that only changes layout is format; any other edit, or a report one file can decide, is lint;
  anything that needs types or other files is analyse (plan/rules.md §1). PHPStan core and Larastan identifiers stay in
  analyse until 1.0.
- **Analyse keeps only what lint and format cannot fix** (2026-11-02, plan/rules.md §2 O5). When a PHPStan class that
  reports an O5 identifier runs, analyse still reports it under the lint rule's ID, so every error shows in lint or
  analyse.
- **Risky rules are lint.** `pun format` is always safe on save; on a project migrated from pint.json,
  `pun check --fix` writes the same bytes as `pint`.
- **The 40 code-deleting format fixers move to lint** (unused imports, useless else, combine issets, ...; list in
  plan/commands.md §5). They stay token fixers in the same priority-ordered pass, so Pint parity holds.
- **No `pun upgrade`.** PHP, Laravel, PHPUnit and Pest upgrades and codemods are lint groups (`lint/laravel-13/...`).
  PHPDoc type tags (`@phpstan-param`) are kept; `pun migrate --phpdoc` rewrites them (opt-in, apps only).
- **`pun lint --fix` doesn't format** (Rector doesn't); `pun check --fix` does both.
- **`pun migrate`** moves pint.json, .php-cs-fixer.php, rector.php and phpstan.neon onto pun.toml completely. It means
  config migration, not code upgrades.
- **`pun init`** asks three questions (format preset, lint preset, analyse preset), offers `pun migrate` when old configs
  exist, writes only the choices, runs one `pun check` and offers fix and baseline. `empty` is not offered (assistant's
  default).
- **No workflow wiring.** Neither migrate nor init edits composer scripts, CI, hooks or editor settings. Agent skills
  (`pun-init`, `pun-migrate`) will do that later.
- **`pun config`** prints the resolved config; **`pun explain <rule>`** a rule's docs and upstream names;
  **`pun list-files [--command format|lint|analyse] [-0]`** the files a command checks.
- **A result cache for format, lint and check** (2026-11-15). `pun format`, `lint` and the format and lint parts of
  `pun check` reuse a file's result (clean, or its findings and diff) from an earlier run with the same key: the file's
  path and content, the command, the resolved config, the flags, the verbosity and agent mode, the PHP version and the
  binary; a lint result that read the project's codebase also keys on a fingerprint of the project. A file a fix run
  wrote, a run error and a contained Mago panic are not kept. Keeping findings, not only clean files, means a warm run
  with no change never scans the project. One cache file per project under `<cache dir>/results/`; `--no-cache` or
  `PUN_NO_CACHE=1` turns it off. `pun analyse` (and check's analyse half) has no cache yet.
- **No LSP** until after 1.0's commands.
- **No compatibility-only flags** (Pushpak, 2026-11-23, before the first beta). `pun format`, `lint` and `check` drop
  `--bail`, `--cache-file`, `--ansi`/`--no-ansi` (`--color` covers them), `--format=txt|xml`, `--stdin` (`-` as the
  path), `--since` and `PHP_CS_FIXER_IGNORE_MISMATCHED_RULES_EXCEPTIONS`; each flag is now clap's unknown argument
  (exit 2). `--max-processes` takes only a positive number. `--staged` outside git is a run error, as `--dirty` is,
  and a config error prints Pint's error box under `--format` or `-q`, as every run error does (plan/format.md §6).

### Config and rules (plan/config.md, plan/rules.md)

- **pun.toml only.** Commands never read pint.json, .php-cs-fixer.php, rector.php or phpstan.neon; only `pun migrate`
  (and the harness) does. Without pun.toml: "No pun.toml found. Run `pun migrate`, or `pun init` for a new project."
  There is no `pint` argv[0] alias.
- **Rule IDs:** `<command>/<group>/<name>` in kebab-case (`format/imports/ordered`). One fixed group list shared by all
  three commands: topic groups, ecosystem groups (`laravel`, `pest`, `phpunit`, `doctrine`) and one upgrade group per
  target. Intent (correctness, style) and fix safety are data, not part of the name. Format's names: plan/format.md §8.
- **No aliases.** Renames are breaking, and that's fine until 1.0. An old or upstream name in pun.toml is an error that
  names the Pun ID.
- **No compatibility-only keys or options** (Pushpak, 2026-11-23, before the first beta): `pun analyse` has
  no `--memory-limit` and no `table` or `prettyJson` format; the 12 PHPStan parameters Pun's analyser doesn't read
  (`NO_READER` in scripts/gen-phpstan-parameters.py) are not rule options, so migrate reports them; and pun.toml keys
  from before the beta (a top-level `preset`, `[format] paths`, `preset = "per"`/`"symfony"`, `fix = "apply"` or
  `"safe-only"`, `severity`, the `"info"` level) fail as ordinary unknown keys or values, with no message of their own.
- **Indent, line ending and `not-name`** (Pushpak, 2026-11-24): format's indent and line ending are the options of
  the rules that check them, `"whitespace/indentation-type" = "tabs"` (`spaces` default) and
  `"whitespace/line-ending" = "crlf"` (`lf` default); every fixer uses them, as PHP-CS-Fixer's `setIndent()` and
  `setLineEnding()` do, and migrate maps those two calls onto them (2-space indent is reported). `[format] not-name`
  is back (reverses 2026-11-23); migrate maps Pint's and PHP-CS-Fixer's `notName` onto it.
- **Format presets:** `laravel` (default), `psr12`, `empty`. Migrate expands `per` and `symfony`.
- **Rule options are TOML-native**, not PHP-CS-Fixer's; migrate translates upstream options.
- **Lint presets and Rector sets** (2026-11-24, below): `[lint] preset = "recommended"` (init's default) plus
  `[lint] sets = ["rector/dead-code"]` for Rector's exact sets.
- **Lint levels follow oxlint:** `"off" | "warn" | "error"` per rule or group, options in a table with `level`; only
  `error` fails; enabled rules default to `error`; `--deny-warnings`, `--max-warnings <n>`, `-A/-W/-D`,
  `[[lint.overrides]]` per path.
- **`--fix` applies every fix of every enabled rule**, as Rector does. No `--unsafe`, no `fix = "apply"` or
  `"safe-only"`; `fix = "off"` makes a rule report-only; safe/unsafe stays a label in the output.
- **Analyse presets:** `basic` (PHPStan 0-1) < `essential` (2-3) < `recommended` (4-5, default) < `strict` (6-8) < `max`
  (9-10), under `[analyse] preset`. There is no top-level `preset` and no shared lint/analyse tier.
- **PHPStan level presets** (2026-11-24, Pushpak): `[analyse] preset = "phpstan/level_0"` to `"phpstan/level_10"` and
  `"phpstan/level_max"` run exactly what `phpstan analyse --level N` runs with default parameters: core rule classes
  of that level and below (mapping.toml `level`), the level's type switches, no opt-in, strict-rules or
  deprecation-rules rules, bleeding-edge rules only with `bleeding-edge = true`, Larastan's default rules with Laravel
  on. The PHPStan checks that are lint rules in Pun come on in `[lint]` too, so `pun check` matches. Pun's five presets
  stay separate. Naming matches the Rector sets (`rector/<set>`).
- **Analyse rules are on or off**; every finding is an error.
- **No numeric levels.** `[analyse] level` and `preset = 5` are errors naming `phpstan/level_5`. Migrate writes the
  PHPStan level preset (`level: max` becomes `phpstan/level_max`) plus only what the config changes; when interactive
  with `--offer-preset` it offers Pun's closest preset with a count of the new problems it would report.
- **Laravel, Pest and PHPUnit turn on by themselves** from composer.lock, with their version rules; a group can be
  switched off. `[php] version` comes from composer.json's `require.php`; the config value only overrides it.
- **`[files]`** (paths, exclude) is shared by every command, and each command's `exclude` adds to it (assistant's
  default, Mago's model).
- **Unsupported items** (an unported rule, a custom fixer class, Rector's Symfony, Doctrine and downgrade sets, a PHPStan
  extension that isn't built in, a project's own PHPStan rules): `pun migrate` names each one, skips it, asks for a PR to
  shipfastlabs/pun, and exits 0 when the rest migrated. A hand-written pun.toml naming an unknown or unported rule is a config
  error (exit 2).
- **No PHP fallback.** Pun never runs PHP-CS-Fixer, Pint, Rector or PHPStan for a rule it lacks, and embeds no PHP.
  System PHP is only the test oracle.
- **One-to-one with upstream** (2026-10-17): every Pun lint rule maps to exactly one non-deprecated Rector (or risky
  PHP-CS-Fixer) rule and every analyse rule to one non-deprecated PHPStan, Larastan, strict-rules or deprecation-rules
  rule, checked against the pinned tools and their websites. A rule upstream deprecates, or registers wrongly, is
  not supported.
- **All of Rector but its deprecated rules** (Pushpak, 2026-11-23; replaces "Rector scope for now" of 2026-10-17):
  every rule of Rector 2.8.4, rector-laravel, rector-phpunit, rector-symfony, rector-doctrine, rector-downgrade-php
  and the Pest plugin is ported, except the ones upstream deprecates and Rector's post-processors (not rules). Rules
  outside the eight sets join the groups their upstream set names; Symfony and Doctrine rules run only when
  `[extensions]` turns that ecosystem on, and the downgrade rules only when you name their group (they undo modernize).
- **All lint rules are 1.0** (2026-10-26): the PHPUnit and Pest lint rules and the lint rules in no set are part of the
  1.0 bar. mapping.toml has no `later` flag.
- **Analyse without Pest or PHPUnit support for 1.0** (2026-10-18): test files are analysed like any other PHP code,
  with no Pest plugin or PHPUnit typing (analyse 7 moves after 1.0). A project that doesn't want them analysed
  excludes them by glob: `[analyse] exclude = ["tests/**"]` removes matching files from both the analysis and the
  symbol scan (PHPStan's `excludePaths.analyseAndScan`); vendor/ is still read for symbols.
- **Symfony, Doctrine and downgrade rules stay out** (Pushpak, 2026-11-24; narrows "All of Rector but its deprecated
  rules" of 2026-11-23): rector-symfony, rector-doctrine and rector-downgrade-php, and the Symfony/Doctrine/JMS/Behat
  rules of Rector core, are not ported; `pun migrate` names them as unsupported. The other unported Rector rules
  are being ported in another thread. `laravel/prefer-pivot-class` is undecided.
- **Lint gets a ladder plus exact Rector sets** (Pushpak, 2026-11-24; replaces "lint presets are sets you tick" of
  2026-10-17): `[lint] preset` is one of Pun's own tiers, each including the one below (names and contents are the
  assistant's call), and `[lint] sets` takes `rector/<set>` sets that match the Rector set exactly. `pun migrate` writes
  only `rector/*` sets (plus single rules); `pun init` writes a tier (`recommended`). Built 2026-11-24 (plan/lint.md §8).
  Today's eight sets (`dead-code`, `modernize`, ...) are dropped; each becomes its `rector/*` twin with exactly Rector's
  members, its PHP-CS-Fixer and Mago rules move into the tiers, and an old set name is a config error naming the new one.
  Rector set names carry over exactly, prefixed by package: `rector/dead-code`, `rector/type-declaration`,
  `rector/php84`, `rector-laravel/laravel-code-quality`, `rector-phpunit/phpunit-code-quality`, `pest/coding-style`;
  `withPhpSets()` is `rector/php-sets` (follows `[php] version`).
- **Rector rules that Pun has as format rules stay format rules** (Pushpak, 2026-11-24): the Rector rules mapped to a
  `format/` rule (11 across dead-code, code-quality and coding-style, plus a few PHP-set rules) get no lint copy, and
  format and lint rules are not combined.
- **Duplicate lint rules are merged** (2026-11-15, plan/rules.md §3): rules that duplicated another (usually a
  PHP-CS-Fixer fixer and its Rector port) are merged into one; the keeper's `merged` and `replaces` fields record the
  upstream names and old IDs, `pun migrate` maps every upstream name to the keeper, and old IDs error with the new one.
- **Scanned and bootstrap files carry over** (Pushpak, 2026-11-23): `[analyse] scan` holds PHPStan's `scanFiles` and
  `scanDirectories`, `[analyse] bootstrap` its `bootstrapFiles`, and `pun migrate` copies them (not the ones under
  vendor/). Pun cannot run a bootstrap file, so it reads its symbols, as for a scanned file, and Larastan its macros.
- **Analyse rule options are checked** (Pushpak, 2026-11-23): a rule's options are the kebab-case PHPStan parameters
  it reads (`[phpstan-parameters]`); another key, or a value that is not a bool (a list of strings for Larastan's
  path and method lists), is a config error.
- **Upgrades below the floor too** (Pushpak, 2026-11-23; replaces "No upgrades below the floor" of 2026-10-17):
  Rector's php-5.3 to php-8.3 upgrade rules and the Laravel, PHPUnit and package upgrade rules below the current
  majors are ported. Code on PHP 8.3+ can still be written the old way, which they modernize.
- **PHP 8.3 is the floor** (Pushpak, 2026-11-23; was 8.4): a `require.php` below 8.3 is a config error, and with no
  `require.php` the target is 8.3. Rules that write PHP 8.4 syntax or call PHP 8.4 functions run only on an 8.4+
  target: the `php-8.4` group, the rules whose `min_php_version` is 8.4, and `format/operators/new-expression-parentheses`
  unless it adds parentheses.
- **Carbon's PHPStan extension is built in** (Pushpak, 2026-11-24): `[extensions] carbon = "on"` (`pun migrate`
  and `pun init` write it when composer.lock locks nesbot/carbon) adds Carbon's bootstrap file, which declares
  `Carbon\DatePeriodBase`. It also gives every class that implements `CarbonInterface` the macros that
  `X::macro('name', ...)` calls register in the analysed, scanned and bootstrap files. Pun reads those calls
  statically, as it reads Larastan's.
- **phpstan-mockery is built in** (Pushpak, 2026-11-25): `[extensions] mockery = "on"`. `pun init` and
  `pun migrate` write it when composer.lock locks mockery/mockery or phpstan/phpstan-mockery, and `pun migrate` also
  when phpstan.neon includes phpstan-mockery. It has no rules and no pun.toml options.
- **spaze/phpstan-disallowed-calls is built in** (Pushpak, 2026-11-25): `[extensions] disallowed-calls = "on"` runs
  the `disallowed` analyse group. Its neon parameters are rule options (`[phpstan-parameters]`), not an
  `[extensions.<x>]` table. `pun migrate` writes the switch from phpstan.neon: `"on"` when PHPStan loads the package,
  `"off"` when it doesn't and composer.lock locks it, so Pun reports nothing PHPStan didn't.
- **tomasvotruba/type-coverage is built in** (Pushpak, 2026-11-25): `[extensions] type-coverage = "on"` runs the
  `type-coverage` analyse group, with its parameters as rule options and migrate's switch as for disallowed-calls.
  `pun analyse` keeps an error without an identifier (its measure mode) and one whose identifier an extension's
  config entry names (`Project::extension_identifiers`, for disallowed-calls' `errorIdentifier`).

### Engines

- **Format:** PHP-CS-Fixer's token fixers on Pun's own lexer (not mago-syntax tokens; reference/tokens.md). Files run
  in parallel, one worker per core. Blade defaults to Node + Prettier; the native formatter (crates/pun-blade) is opt-in with
  `[format] blade = "native"`. A Pun
  reprinting preset (`preset = "pun"`) comes after 1.0.
- **Lint:** rules return text edits on byte ranges found through Mago's syntax tree; format tidies the layout after.
  No php-parser printer. Parity is `format(pun lint --fix)` = `format(rector process)`. Mago's rules are normal lint
  rules; there is no `--mago`.
- **Analyse** (assistant's call, delegated): Mago's analyser for inference, one Pun rule per PHPStan rule in the
  mapping, messages may be reworded. **Mago's issues are evidence, not rules** (2026-10-18): each rule is a Pun check
  that reads Mago's inferred types, with PHPStan's semantics for that rule and preset; a Mago issue is used directly
  only where it is exactly the same check. Laravel is a built-in Mago plugin (Pest after 1.0). Built-in symbols come
  from PHPStan's reflection (crates/pun-phpstan/data/symbols.json). Baselines are Pun's own
  (`pun analyse --generate-baseline`, pun-baseline.toml); migrate never copies a PHPStan baseline.
- **Extensions** (2026-11-15, plan/extensions.md): Laravel, Pest and PHPUnit support sits behind one Rust `Extension`
  trait, compiled in. A project turns them on only in pun.toml's `[extensions]`; `pun extension list` shows which are
  on and why. Mockery, Livewire, Filament and the like come later as extensions.
- **Mago** from crates.io, pinned `=1.61.0`, bumped together; mago-analyzer, mago-codex, mago-syntax and
  mago-phpdoc-syntax are vendored with patches in `third_party/`, each with its PATCHES.md.
- **FrankenPHP** (for the later `pun run`): link libphp through a Rust SAPI first, FrankenPHP later (assistant's call).

### Output (plan/output.md)

- **Pun's own human output** for every command, modelled on oxfmt, Biome and Ruff: file lines, problem blocks with code
  by default (`--concise` for one line), one summary line. Pint's human screen is not copied.
- **`pun check` groups by step** like Vite+'s `vp check`: one status line per step, its problems under it, one summary.
- **Brand colours** from docs/design/tokens.json at truecolor, 256 and 16 colours; `NO_COLOR`, `--color`, ASCII fallbacks.
- **GitHub annotations** are automatic under `GITHUB_ACTIONS`; `--format=github` forces them. Clean files print nothing
  (`-v` adds a dim line).
- **Exit codes and machine formats** stay Pint- and PHPStan-compatible. Exit 2 means Pun couldn't run.
- **Agent mode:** under a coding agent every command prints compact `path:line:col rule message` lines, not JSON.

  mapping.toml. A rules directory with search across upstream names and URL-kept filters at launch. One migration

### Engineering
